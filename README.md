# STACKER

원버튼 블록 스태킹 게임. 탭/스페이스로 움직이는 블록을 쌓고, 어긋난 만큼 잘려나간다.
판정 범위 안에 딱 맞추면 PERFECT 콤보 — 점수 보너스와 함께 블록 폭이 회복된다.

## 튜터리얼

시작 화면의 `처음이신가요? 튜터리얼 →` 로 들어간다. 기록도 난이도 선택도 없는 첫 방문이면
자동으로 뜨고, 한 번 마치거나 건너뛰면 다시 뜨지 않는다 (`stacker-tutorial-done`).

블록 3개로 세 가지를 차례로 보여준다. 판정이 가장 넉넉한 `SEED` 기준으로 진행한다.

1. 판정에서 벗어난 자리에서 멈추게 하고 놓게 한다 → **어긋난 만큼 잘려나간다**
2. 딱 맞는 자리에서 멈추게 하고 놓게 한다 → **PERFECT 는 잘리지 않고 폭이 넓어진다**
3. 아주 느리게 움직이는 블록을 직접 맞히게 한다 → **콤보**

1·2 에서 블록은 처음부터 자리에 놓여 있지 않다. 실제 게임처럼 화면 밖에서 제 속도로
흘러 들어오다가 정해진 자리에서 멈춘다 — 움직이는 것을 먼저 보여야 무엇을 맞히는
게임인지 전달된다. 기다리기 답답하면 눌러서 건너뛸 수 있고, 이때의 누르기는 블록을
놓는 것이 아니라 빨리 감기다.

**어떤 경우에도 게임 오버로 끝나거나 빠져나갈 수 없는 상태가 되지 않는다.** 3번에서
블록의 이동 범위를 탑 주변으로 묶어 완전히 빗나가는 일 자체를 막았고, 빗나가면 그것을
콤보가 끊긴다는 설명으로 쓴 뒤 한 번 더 준다. 그것마저 놓치면 마지막 시도는 이동
범위(±36px)를 판정(46px)보다 좁게 만들어 반드시 성공시킨다.

튜터리얼 점수는 리더보드에 남지 않는다.

## 난이도

시작 화면에서 고른다. 선택은 저장되어 다음 판에도 유지된다.

| | 뜻 | 블록 속도 | PERFECT 판정 | 폭 회복 |
|---|---|---|---|---|
| **SEED** | 씨앗 | 2.6 → 5.6 | 10px | +6px |
| **SPROUT** | 새싹 | 3.2 → 7.4 | 7px | +4px |
| **BLOOM** | 개화 | 4.0 → 9.4 | 5px | +2px |
| **CROWN** | 왕관 | 5.0 → 11.8 | 3px | 없음 |

속도 단위는 60fps 기준 프레임당 픽셀이며, 실제로는 경과 시간에 비례해 움직인다 —
화면 주사율이 60Hz든 120Hz든 같은 속도다. 속도는 층이 올라갈수록 빨라져 표의 최대치에서 멈춘다. `SPROUT` 이 기존 기본값이고,
`CROWN` 은 폭 회복이 없어 한 번 좁아지면 되돌릴 수 없다.

점수는 착지 1점, PERFECT 는 `1 + 콤보` 점이다 (첫 PERFECT 2점, 연속으로 3점, 4점 …).
좌측 상단 패널이 이 규칙과 **다음 PERFECT 로 얻을 점수**를 실시간으로 보여준다.

## 리더보드

**`전체` 와 `내 기록` 두 가지를 본다.** 기본은 전체 랭킹이고, 단계 탭으로 단계를 바꾼다.
상위 목록에 내가 없으면 **내 순위가 맨 아래에 고정 행으로** 붙는다.

**단계마다 따로 센다** — 전체는 TOP 10, 내 기록은 TOP 5. 서로 다른 단계의 점수를 한 줄에
세우면 비교가 되지 않기 때문이다.

### 전체 랭킹 (Supabase)

Supabase REST 를 `fetch` 로 직접 부른다. **JS 클라이언트 라이브러리는 쓰지 않는다** —
"외부 라이브러리 없음" 컨벤션을 지키기 위해서다. 코드에 박힌 키는 공개용(publishable)이라
HTML 에 그대로 들어가도 된다. 실제 방어는 서버의 RLS 정책과 `CHECK` 제약(단계 이름,
점수 상한 3000, 이름 길이)이 한다.

플레이어는 `localStorage` 의 익명 ID(`stacker-player-id`)로 구분한다. 로그인은 없다.

**네트워크가 죽어도 게임은 그대로다.** 6초 안에 응답이 없거나 실패하면 자동으로 내 기록을
대신 보여준다. 제출도 게임을 막지 않으며, 실패해도 로컬 기록은 이미 저장돼 있다.

> 부정 점수는 원리적으로 막을 수 없다 — 게임이 전부 브라우저에서 돌기 때문이다. 지금은
> 서버의 `CHECK` 제약으로 말이 안 되는 값만 거른다. 더 필요해지면 드롭 시점을 보내
> 서버가 리플레이해 점수를 계산하는 방식이 가능하다(점수에 영향을 주는 난수가 없어
> 재현된다). 그때는 서버 코드가 필요하다.

우측 상단 최고 기록은 **지금 고른 단계의 것**이며, 라벨에 단계 이름을 단계 색으로
붙인다 (`SPROUT 최고 기록`). 라벨이 "최고 기록" 뿐이면 기본 선택인 쉬운 단계의 점수가
게임 전체의 기록처럼 읽힌다. 기록이 없는 단계는 숫자 대신 `—` 를 보여준다.

플레이 중에 넘어야 할 점수가 화면에 있어야 하므로 이 자리는 리더보드로 대신할 수 없다.
리더보드는 게임이 끝나야 보이기 때문이다.

## 실행

배포판: https://eastar80.github.io/stacker/

빌드 과정 없음. 정적 HTML 한 파일이 전부다.

```bash
# 브라우저에서 바로 열기
open index.html          # macOS
start index.html         # Windows

# 또는 로컬 서버로
npx serve .
```

## 구조

- `index.html` — 게임 전체 (HTML + CSS + JS 단일 파일)
  - Canvas 렌더링, Web Audio 칩튠 시퀀서(음원 파일 없음), TOP 5 리더보드
  - 효과음도 Web Audio 합성이다. PERFECT 는 콤보마다 반음 올라가는 상승 아르페지오,
    어긋난 착지는 둔탁한 충격음, 게임 오버는 단조 3음 하강 뒤 바닥 충격.
  - 우측 상단 버튼은 음악과 효과음을 함께 끈다.

## 저장

리더보드는 저장 어댑터를 통해 환경에 맞게 저장된다:
1. `window.storage` — Claude.ai 아티팩트 환경
2. `localStorage` — 일반 브라우저 (배포 시 이 경로 사용)
3. 메모리 — 둘 다 불가할 때 폴백

저장 키는 단계별 리더보드(`stacker-boards`), 마지막 이름(`stacker-lastname`),
난이도 선택(`stacker-difficulty`) 세 개다.

튜터리얼 완료 여부(`stacker-tutorial-done`)까지 하면 넷이다.

단계 구분이 없던 시절의 기록(`stacker-leaderboard`)은 첫 실행 때 `stacker-boards` 로
옮긴다. 그때의 기본 설정이 지금의 `SPROUT` 이므로 단계 표시가 없는 기록은 `SPROUT` 으로
넣는다. 예전 키는 지우지 않고 그대로 남겨둔다.
